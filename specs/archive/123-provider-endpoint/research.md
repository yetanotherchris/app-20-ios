# Research: Model Catalog and Provider Endpoint

## 2026-09-28 decisions

- Decision: extend the existing serialized SecureStore TOML snapshot for endpoint and endpoint-indexed model preferences. Rationale: a single setItemAsync is already the spec 121 commit point and prevents mixed endpoint/key/list activation. Alternatives: separate records introduce partial-write recovery complexity.
- Decision: use Expo fetch with redirect error for provider and catalog calls. Rationale: installed Expo 57 fetch forwards redirect mode into its native iOS URLSession delegate; React Native whatwg-fetch alone does not guarantee it. Verify native behavior on device separately. Alternatives: checking response URL is too late to prevent disclosure.
- Decision: retrieve every discovery entry, including OpenRouter output_modalities=all, support next links and explicit cursor metadata, and reject unsafe, looping or incomplete pagination. Rationale: [OpenRouter catalog](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) documents offset/limit, links and total_count; omission of pagination returns a full list. [OpenAI models](https://developers.openai.com/api/reference/resources/models/methods/list) documents data/id with no pagination. Do not assume models are chat-capable.
- Decision: retain complete catalog in endpoint-keyed memory; protected model choices persist independently. Rationale: failures should not clear choices, and cache need not survive relaunch. Alternatives: plaintext catalog persistence is unnecessary.
- Decision: selection refs feed both pre-lock and post-lock conversation snapshots; send captures a committed settings snapshot before submitting. Rationale: existing autosave rewrites model from base after locking, and asynchronous key lookup alone could mix import revisions.

Evidence inspected: src/secrets/secretService.ts, src/settings/SettingsSheet.tsx, src/chat/IosChatScreen.tsx, src/storage/schema.ts, installed node_modules/expo/src/winter/fetch/fetch.ts and node_modules/expo/ios/Fetch/NativeRequest.swift. [Expo fetch documentation](https://docs.expo.dev/versions/latest/sdk/expo/#expofetch-api) describes native streaming support. No new dependency or unresolved technical choice remains. Constitution remains an unratified template.

Decision: guard retry/regenerate before app-20-llmchat invokes reopenOperation. Installed useChatSession.js clears assistant content before the host request callback; rejecting only inside transport is too late to preserve transcript. Retained conversation selection feeds both autosave snapshots even when current sending selection becomes invalid. Unlisted row metadata is kept only for the endpoint editing session, while enabled preferences remain durable.
