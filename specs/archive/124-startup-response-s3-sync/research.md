# Research

- **Decision**: Replace the native queue-only service with a durable coordinator; retain the standalone MirrorQueue API for compatibility. **Rationale**: blind queue flushing bypasses timestamp/conflict/deletion policy. **Alternatives**: running syncOnce then the old queue cannot enforce holds or configuration fencing.
- **Decision**: Atomic private JSON state holds operations, remote candidates and recovery bytes. **Rationale**: one state commit prevents partial hold/queue transitions and keeps recovery out of history. **Alternatives**: canonical conversation copies would create duplicate entries; memory-only holds fail relaunch acceptance.
- **Decision**: RFC3339 parser uses calendar checks and arbitrary fractional precision. **Rationale**: string/Date comparisons mishandle offsets, impossible dates and fine precision. **Alternatives**: millisecond Date-only comparisons lose required ordering.
- **Decision**: Hash full configuration with SHA-256 and invalidate results on settings changes. **Rationale**: credential changes need fresh reconciliation without persisting credentials. **Alternatives**: bucket-only identity redirects old operations.
- **Decision**: Use [npm s3rver](https://github.com/jamhall/s3rver) with AWS SDK over loopback HTTP for automated integration, alongside deterministic fake ports for concurrency. **Rationale**: exercises actual XML listing, missing objects, object bodies and prefix contract without cloud credentials. **Alternatives**: mocks alone do not verify protocol compatibility; Docker/cloud servers do not meet the requested npm server setup.
- **Decision**: Short local mutation serialization plus post-read checks, separate from serialized network work. **Rationale**: downloading cannot overwrite a concurrent save and network never blocks local sending.
