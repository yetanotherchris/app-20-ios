# Native model and endpoint acceptance

Requires Maestro, an installed iOS development build (`com.app20.chat`) and reachable HTTPS fixture endpoints. Run `npm run test:e2e` for the whole suite; for fixture flows use `maestro test -e PROVIDER_A=https://fixture-a.example/prefix/v1 -e PROVIDER_B=https://fixture-b.example/v1 -e UNSUPPORTED_PROVIDER=https://fixture.example/unsupported tests/e2e/models`. Use real fixture addresses; the example addresses do not host services. No private credentials are needed.

Provider A returns a `data` list with `fixture/one`, `fixture/two` and `fixture/shared`; Provider B also lists `fixture/shared`. Both stream OpenAI-compatible SSE replies containing `model=<exact submitted model>` followed by `[DONE]`, and record request route/model for inspection. The unsupported provider returns 404 for `/models` but accepts manually selected identifiers. `catalog.yaml` verifies exact manual addition, case-insensitive search, toggles and relaunch persistence without depending on a particular public catalog. `endpoint.yaml` verifies invalid drafts, prefix persistence and endpoint-isolated preferences. `recovery.yaml` verifies failure/retry retention and manual identifiers. `send.yaml` verifies successive exact sends and restored selection/transcript.

Additional device scenarios from the specs require fixture control: paginated catalogs with names/IDs, empty catalogs, unauthorized/malformed responses, network loss, disabled selections outside the authored provenance flow, S3-downloaded JSON lifecycle, interrupted protected writes, in-flight settings changes and cross-origin redirects. Use the quickstart guides for these scenarios; unit/component and HTTP S3 checks cover their data logic but do not establish native UI, lifecycle, file-picker, SecureStore or redirect acceptance. For redirect acceptance, configure chat/catalog to redirect to a second recording origin and assert that origin receives no authenticated request.

This WSL environment has neither Maestro nor xcrun and cannot run an installed iOS build. All seven flows and additional native scenarios remain unverified until executed on a device/simulator.

## Provenance and import fixture preparation

Run provenance and legacy flows separately on disposable installations, preserving seeded state. Generate exact fixtures with `python3 tests/e2e/models/prepare-fixtures.py --provider-a "$PROVIDER_A" --provider-b "$PROVIDER_B"`; the script prints a new temporary fixture directory. Its keys and transcripts are public synthetic values. On a stopped, disposable simulator installation, locate the data container with `xcrun simctl get_app_container booted com.app20.chat data`. Copy the generated `conversations` directory into that container's `Documents` before launching; it includes the manifest and three exact conversation files. Use a fresh disposable installation for each flow, since replacing that test manifest is intentional setup. No real history should be present. Seeded local JSON exercises the same legacy parser used for downloaded S3 conversations; HTTP S3 provenance transfer is independently covered in Vitest.

Run `provenance.yaml` with A and B configured to accept `fixture/shared`. It verifies restoration at A, live invalidation when switching to B despite the identical ID, blocked sending with preserved transcript, restoration under B still requiring confirmation, and a successful explicit choice. Run `legacy.yaml` from fresh OpenRouter defaults with the generated files seeded; it verifies the legacy auto exception, invalidation at another endpoint, explicit confirmation for a non-auto legacy selection and provenance persistence after relaunch.

For `atomic-import.yaml`, make the generated TOML files available in the system document picker's Recents before starting, through iCloud Drive or another Files provider. Open each file through that provider once so its filename appears in Recents. The app does not expose its private Documents directory through Files, so copying these TOML files only into its private sandbox is insufficient. This flow verifies the real file picker, coherent endpoint/key/list import, whole-document rejection of an invalid replacement, explicit empty-list persistence and empty-endpoint reset. Use an installed development build and real fixture addresses, and confirm provider request logs for the newly committed pair. Native protected-write interruption/failure injection is unavailable in this build; termination-during-commit acceptance remains unverified, with failure/relaunch recovery covered by automated protected-storage tests.
